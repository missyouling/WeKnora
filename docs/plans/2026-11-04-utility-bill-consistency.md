# 能耗管理（市电账单）一致性与双列交叉校验（第 33 轮）

## 目标

1. 在途解析/提取的文件不进列表、不计 KPI、不进合计数。
2. 电量明细的线损/加减/计费电量完整；容需量与功率因素明细不再为空。
3. 账单概况「计费数量」= 明细计费电量（四段求和 / 居民 / 容量）。
4. 「电费」列 100% 由明细实算（明细空 → 0.00），「账单电费」列取票面值，
   两列差异 > 0.02 显示「异常」。
5. 全量 17 份历史账单回溯补齐并逐份校验；黄金基准 100% 通过。

## 关键设计

### 后端：确定性补全（`utility_bill_detail_parser.go`）

LLM 对固定表结构偶发漏抽，因此用**票面原文**做确定性解析：

| 解析器 | 输入形态 | 输出 |
|---|---|---|
| `ParseUtilityMeterReadings` | `||正向有功（尖峰）||238.31|250.14|3000||35490|0|18|-1403|34105|` | 8 个数字的 meter 行 |
| `ParseUtilityCapacityDetail` | 平铺键值（需量值/容量/容量电价/输配容量电费…） | 单行容量明细 |
| `ParseUtilityPfDetail` | 平铺键值（功率因数实际值/标准/调整系数…） | 单行力调明细 |

两个必须的护栏：

1. **截段解析**：账单概况里也有「输配容量电费 2000 44000」（2000 是容量），
   全篇 FirstMatch 会把 44,000 读成 2,000。以「输配容（需）量电费 + 功率因数调整电费」
   相邻表头为锚点截段（真机回填事故）。
2. **完整性门禁**：多计量点账单（2025.06/2025.10）文本里有多张电量明细表，
   只解析到第一张就替换会把 12~27 行压成 6 行。判定条件：
   `|解析四段合计 − 零售交易电费四段合计| ≤ max(2, 0.5%)`，不通过时只对空记录兜底。

四段电量（尖/峰/平/谷）的来源顺序：
**费用明细「零售交易电费」四段 qty**（全账单口径） > 电量明细四段。
旧实现只取电量明细，多计量点账单会得到 333,600 / 711,127 的截断值。

### 前端

- `utilityBillOverview.buildOverviewRows`
  - 计费数量：市场化/输配 = 四段求和；线损/系统/政府基金 = 单行全量（取最大）；
    居民 = 居民计费电量；容需量 = 容量；
  - 「电费」列：`capacity_detail` / `pf_detail` 为空 → 0；
  - 「账单电费」列：顶层 `capacity_fee` / `pf_adjust_amount`；
  - 工商业小计 = 5 项（不含容需量）；本期电费 = 工商业 + 居民 + 容需量 + 力调。
- `utilityBillDetail`
  - `meterTotalOf`：只累加四段计费电量（总表/无功不参与）；
  - `touBillKwhOf`：优先取 meter 行计费电量，缺失回落顶层；
  - 用能分析占比分母 = 四段之和（不是账单总电量，否则合计 98.5%）。
- `UtilitiesManagement` / `SolarManagement`
  - 在途文件不再拼 placeholder 行（只保留进度条）；
  - 指标卡去掉二次格式化（`fmtKwh(metricKwh)` 把 "623,932" 变成 0）；
  - 本期电费卡片绑 `grand_total`（票面），不再绑子项合计。
