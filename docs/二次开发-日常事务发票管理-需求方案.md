# WeKnora 二次开发需求方案：日常事务模块（发票管理）

> 项目：WeKnora v0.7.2（腾讯开源 RAG 知识库框架）
> 版本：V1.0（经三轮需求评审确认）
> 日期：2026-09-03
> 状态：已确认，可进入开发



***

## 1. 背景与目标

在 WeKnora 现有平台上进行二次开发，新增「日常事务」模块，首个落地功能为**发票管理**。目标：让企业用户把发票文件（PDF / 图片）上传到平台，依托 WeKnora 既有知识库解析能力 + 新增的 LLM 字段提取能力，实现发票的**自动归档、字段回显、查询、查看、编辑、下载、删除、批量管理**，无需人工登记台账。

**整体范围**：



* 侧边栏新增一级菜单「日常事务」

* 日常事务首页：4 张卡片（发票管理 / 合同管理 / 制度管理 / 奖惩管理），风格与原项目一致

* **发票管理为首个落地功能**；合同 / 制度 / 奖惩仅做占位卡片（点击提示 "功能开发中"）

**非目标（本期不做）**：



* 分享功能（文件级分享无原生能力，后置）

* 合同 / 制度 / 奖惩的实际功能

* 多语言（i18n 仅入 zh-CN）

* 服务端按字段过滤、发票统计报表（列入后续迭代）

## 4. 后端设计方案

### 4.1 新增发票字段提取接口



* **路由**：`POST /api/v1/knowledge-bases/{kbId}/knowledge/{id}/extract-invoice`

* **文件**：`internal/router/routes_knowledge.go` 注册 + `internal/handler/knowledge.go` 新增 handler

* **权限**：复用 RBAC（`OwnedKBOrAdmin` + `KBAccessWrite`，与重解析同级），纳入审计日志

* **职责**：

1. 校验知识条目属于该 KB、`parse_status` 为成功

2. 读取文档解析文本（复用 chunk 读取逻辑）

3. 调用 LLM（复用 KB 的 `summary_model_id`）提取发票字段，**支持单文档多发票，输出发票数组**

4. 同文件内按（发票号 + 销方税号）自动去重

5. 跨文件去重：查询 KB 内已有 `custom_metadata`，命中则标记 `duplicate:true`

6. 非发票内容 → 标记 `not_invoice`

7. 结果写入 `custom_metadata`（`extract_status: success|failed|not_invoice`）

* **幂等**：重复调用时覆盖重写 `custom_metadata`（保留发票 ID 关联）

### 4.2 LLM 提取逻辑



* 提取 Prompt 需明确：发票字段定义、支持多发票、同文件去重规则、非发票判定、金额精确到分、字段缺失留空

* 输出约束为 JSON 数组，后端校验字段类型（金额转 number）后落库

* 模型异常 / 超时 → `extract_status: failed` + `extract_error`，前端可重试

### 4.3 权限与审计



* 复用现有 RBAC 中间件与审计日志机制（`middleware/rbac.go`）

* 提取接口为消耗型操作（LLM 调用），无自动重试，避免重复消耗

## 5. 数据模型

### 5.1 发票知识库（KnowledgeBase）



| 字段                   | 值                                                                                            |
| -------------------- | -------------------------------------------------------------------------------------------- |
| name                 | `日常事务-发票`（只读）                                                                                |
| type                 | `document`                                                                                   |
| indexing\_strategy   | `{ vector_enabled: true, keyword_enabled: true, wiki_enabled: false, graph_enabled: false }` |
| embedding\_model\_id | 向导选择                                                                                         |
| summary\_model\_id   | 向导选择（兼作提取模型）                                                                                 |

### 5.2 知识条目 custom\_metadata（发票）



```
{

&#x20; "kind": "invoice",

&#x20; "invoices": \[

&#x20;   {

&#x20;     "invoice\_no": "发票号码",

&#x20;     "invoice\_code": "发票代码",

&#x20;     "invoice\_date": "2026-08-01",

&#x20;     "invoice\_type": "专票|普票|数电票",

&#x20;     "total\_amount": 1130.00,

&#x20;     "amount": 1000.00,

&#x20;     "tax": 130.00,

&#x20;     "tax\_rate": "13%",

&#x20;     "seller\_name": "销方名称",

&#x20;     "seller\_tax\_no": "销方税号",

&#x20;     "buyer\_name": "购方名称",

&#x20;     "buyer\_tax\_no": "购方税号",

&#x20;     "items": \[

&#x20;       { "name": "商品/服务名称", "qty": 1, "price": 1000.00, "tax\_rate": "13%" }

&#x20;     ],

&#x20;     "void\_flag": false,

&#x20;     "duplicate": false

&#x20;   }

&#x20; ],

&#x20; "extract\_status": "pending|processing|success|failed|not\_invoice",

&#x20; "extract\_error": ""

}
```

**说明**：



* 金额 / 税额 / 价税合计用 `number`（排序、月度统计需要）；税率保留字符串（可能含 "13%"/"免税" 等）

* `duplicate` 仅在跨文件重复时为 true；`void_flag` 表示作废 / 红冲

* 非发票文件：`{ "kind": "not_invoice", "extract_status": "not_invoice" }`

* 关联：列表行 = 一条发票记录，`knowledge_id` 指向父文件，下载 / 预览 / 编辑均定位父文件

## 6. 用户路径（验收主流程）



1. 登录 → 侧边栏「日常事务」→ 首页见 4 卡片

2. 点击「发票管理」→ 首次进入弹出**创建发票知识库向导**（三步）→ 创建成功进入发票列表（空）

3. 右上角「上传发票」→ 选择 / 拖拽发票 PDF（含多张发票）→ 列表出现 "解析中" 行

4. 解析完成自动触发字段提取 → 行状态 "提取中" → "已提取"，**字段回显到列表各列**

5. 点击行 → 右侧抽屉：字段详情 + 原文件预览 + 可编辑保存

6. 下载 / 删除 / 批量删除 / 重新提取 / 重新解析

7. 重复发票自动标记 "重复"，默认不显示，可切换查看并手动清理

8. 非发票文件标记 "未识别"，不污染发票列表

## 9. 风险与注意



* **提取质量依赖 LLM 与文档清晰度**：拍照 OCR 效果波动大，需在提取 Prompt 与失败重试上兜底

* **发票 KB 与普通 KB 并存**：发票 KB 在原知识库列表可见，勿误删；入口做好二次确认

* **多发票 PDF 的字段关联**：列表行与父文件 1:N，删除父文件会级联删除其全部发票行，需提示

* **提取接口消耗 LLM 配额**：无自动重试，失败提示用户手动重试

* **跨文件去重查询**：需在 KB 内扫描已有 custom\_metadata，发票量大时注意查询性能（可后置为 P2）
