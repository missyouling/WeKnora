## 二、三模块差异契约

### 1. 合同管理（沿用现有，补全）

- 知识库：`日常事务-合同`，`scope=contract`。
- 内置分类（沿用现有 2 类）：**服务合同、租赁合同**。
- 字段：`contractFieldLabels.ts` 已定义 40 个契约键（contractNo/contractName/partyA/partyB/signDate/contractAmount/…），保持不动。
- 补全项：
  - 挂载 `BusinessParseStatusBar`；
  - 批量重新提取/重新解析的并发限流 + 状态条联动（对齐发票 `displayProgress`/`pendingFiles` 逻辑）；
  - 分类/字段六同步核查（见第三节）；
  - 每类内置提取规则底稿（参照发票规则固化，基础模式自动填充）。

### 2. 制度管理（`scope=regulation`，字段契约键保持不动）

## 三、六同步核查清单（复刻必含）

**分类名称/顺序/别名** 同步 6 处：
1. 设置抽屉内分类列表（权威源，`categories[scope]` 数组顺序）；
2. 主页面概览卡片分组标题（取 `fleet_group_aliases`）；
3. 主页面概览类型卡片（按 categories 顺序，仅遍历 enabled，禁 by_doc_type）；
4. 工具栏类型筛选下拉；
5. 提取规则面板类型下拉；
6. 上传弹窗类型下拉。

**字段开关四同步**：表头 / 字段筛选器 / 编辑抽屉 / 打印预览。

**其他**：
- 「启用表头」is_default 双向同步；
- 重置 = 恢复 base；
- 列顺序以 categories.subs 数组为唯一权威。

## 六、风险与回滚

- **改名风险**：scope 与字段契约键保持不动，数据零迁移；仅展示名/知识库名变更，风险低。
- **存量数据**：旧奖惩类型记录保留原值，不删除。
- **seed 防覆盖**：后端分类/规则只对缺失项 Create，已存在的不 Update 覆盖。
- **回滚**：每模块独立 commit，可按模块 `git revert`；知识库改名可逆（再次改名）。
